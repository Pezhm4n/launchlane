# Launchlane

دستیار استقرار و بررسی سلامت سرویس، با پیشنهاد مبتنی بر شواهد و تأیید شما پیش از اقدام حساس.

**وضعیت فعلی:** انتخاب‌گر پوشه محلی، بررسی خودکار پروژه Node، بسته خصوصی، بازیابی نتیجه و پیشنهاد/تأیید پایدار ساخته شده‌اند. مسیر اتصال GitHub با CLI رسمی، فهرست مخزن/شاخه/زیرپوشه و دریافت محدود روی commit مشخص پیاده شده است؛ grant واقعی حساب در این محیط تأیید نشده. اتصال لیارا، کلید را پیش از نگهداری رمز‌شده با هویت/تیم/برنامه‌ها بررسی می‌کند؛ shape و مجوز حساب واقعی هنوز به آزمون محدود نیاز دارند. مسیر عادی بررسی مشکل با برنامه/نشانه/صفحه، گزارش ماندگار و نمونه اختیاری ساخته و با transport کنترل‌شده آزموده شده است. انتشار واقعی، قیمت، تشخیص واقعی و اصلاح زیرساخت هنوز تأیید نشده‌اند؛ تأیید پیشنهاد چیزی را منتشر نمی‌کند.

## اجرای محلی

Node 24.15+ از شاخه 24.x و npm لازم است. برای مسیر آفلاین کلید Liara/مدل لازم نیست.

```text
npm ci
npm run setup:local
npm run dev
```

صفحه پیش‌فرض: `http://127.0.0.1:3000`. کلید ورود را از `.local/operator-access.txt` به‌صورت محلی بردارید؛ این فایل و `.env.local` خصوصی‌اند و وارد Git نمی‌شوند. setup مقدار موجود credentialها را حفظ می‌کند. پس از تغییر config، server را restart کنید. برای اجرای production:

```text
npm run build
npm start
```

در terminal جدا، در حالی که server اجراست:

```text
npm run lint
npm run typecheck
npm run test:domain
npm test
```

`npm test` دو smoke اجرای server است. `test:domain` policy، persistence، source و قرارداد transport/خطا را می‌سنجد. برای پورت دیگر، `LAUNCHLANE_ORIGIN` و پورت اجرا را با هم عوض کنید و برای smoke، `TEST_BASE_URL` را نیز تنظیم کنید.

برای HTTP و UI، پس از build و بدون نیاز به اجرای server جداگانه:

```text
npm run test:http
npx playwright install chromium
npm run test:browser
```

این دو دستور server تولیدی موقت با محدوده مصنوعی و کلیدهای provider خالی ایجاد می‌کنند. آزمون مرورگر ۹ عرض از ۲۸۰ تا ۱۲۸۰ پیکسل، انتخاب/بازیابی پروژه، اتصال حساب‌ها با پاسخ کنترل‌شده، approve/reject، خطا، لغو، کیبورد، متن ۲۰۰٪ و axe را می‌سنجد؛ تصاویر و گزارش در `.artifacts/` محلی می‌مانند. داده حساب و نتایج provider در تست مصنوعی‌اند؛ نتیجه شاهد اتصال حساب واقعی، deploy یا کیفیت مدل نیست.

## استفاده از میز کار

1. وارد شوید و «انتخاب پوشه پروژه» یا «انتخاب از GitHub» را بزنید. نمونه فقط با «امتحان با پروژه نمونه» انتخاب می‌شود. انتخاب‌گر محلی پوشه‌های مجاز سرور همین رایانه را می‌خواند؛ upload پوشه دستگاه مرورگر نیست. محدوده آن با `LAUNCHLANE_WORKSPACE_ROOT` تنظیم می‌شود؛ کل دیسک مجاز نمی‌شود.
2. فایل‌ها خودکار و بدون اجرای script بررسی و بسته خصوصی آماده می‌شود. نام/حجم فایل‌ها قابل بازبینی است؛ مرحله دستی بسته‌سازی یا واردکردن دوباره پورت تشخیص‌داده‌شده ندارید. پروژه ناقص یا پورت نامعلوم سؤال مشخص ایجاد می‌کند.
3. از «حساب‌ها»، لیارا را متصل کنید. کلید به‌جای صرف ذخیره‌شدن، با سه GET محدود برای هویت، تیم ثابت و برنامه‌ها بررسی می‌شود. تیم مجاز را مسئول نصب در `LIARA_TEAM_ID` تعیین می‌کند؛ کاربر نام برنامه را از فهرست انتخاب می‌کند. allowlist مدیر، اگر تنظیم شده باشد، محدودیت بالادست است. اتصال فقط یک app انتخابی را مجاز می‌کند و مجوز تغییر همه برنامه‌ها نیست.
4. پیشنهاد شامل مقصد، فایل‌های همان نسخه، اثر و وضعیت نامشخص هزینه است. تصمیم در سرور به همین ورودی‌ها و revision GitHub متصل می‌شود؛ انتخاب تازه یا تغییر فایل‌ها تأیید قدیمی را باطل می‌کند. نسخه‌های v1/v2 تاریخی حفظ می‌شوند و جریان پروژه از ActionSpec v3 استفاده می‌کند.
5. با نوسازی یا Back/Forward، نتیجه ذخیره‌شده بازیابی و تازگی فایل‌ها بررسی می‌شود. بازیابی، تأیید منقضی را تمدید نمی‌کند. ثبت تأیید، انتشار و سالم‌شدن سایت وضعیت‌های متفاوت‌اند؛ دو مورد آخر هنوز زنده تأیید نشده‌اند.

برای ورود GitHub روی Windows x64، مسئول نصب یک‌بار `npm run setup:github` را اجرا کند. نسخه رسمی 2.103.0 با checksum بررسی و فقط در ابزارهای محلی نصب می‌شود؛ PATH یا ورود سراسری تغییر نمی‌کند. ورود از device flow ابزار رسمی و با grant انسان انجام می‌شود؛ credential باید در keyring باشد. مجوزهای گسترده CLI پیش از ورود توضیح داده می‌شوند؛ برای محصول عمومی GitHub App می‌تواند محدودتر باشد. [دلیل انتخاب روش](docs/decisions/0001-account-connections.md) و محدودیت‌ها ثبت شده‌اند.

برای «بررسی مشکل سایت»، برنامه متصل و نشانه مشکل را انتخاب کنید. نشانی عمومی امن سایت را می‌توان در حساب‌ها ثبت کرد؛ این کار دامنه لیارا را تغییر نمی‌دهد. پس از فعال‌شدن مجاز خواندن، اطلاعات همان برنامه و صفحه جمع‌آوری می‌شود؛ توضیح خودکار علت یک اقدام جدا و وابسته به آماده‌بودن مدل است. بررسی دوباره فقط پاسخ همان صفحه را می‌خواند و هیچ اصلاحی اجرا نمی‌کند. گزارش ابتدا مشکل، علت احتمالی، اقدام و نتیجه تازه را نشان می‌دهد؛ شواهد اولیه و تازه قابل بازکردن‌اند. داده ناکافی، علت قطعی تولید نمی‌کند.

«امتحان با نمونه اختلال» اختیاری و در تمام گزارش مشخص است؛ داده و تحلیل آن simulated/scripted هستند و هیچ تماس مدل/حساب ندارند. تغییر نامرتبط، 500 را حفظ می‌کند. نتیجه عادی و نمونه در SQLite متعلق به همان کاربر نگهداری و پس از جابه‌جایی، نوسازی یا ورود مجدد بازیابی می‌شوند؛ مرورگر فقط شناسه غیرحساس در URL دارد. تحلیل در حال اجرا با نوسازی تکرار نمی‌شود و پس از قطع فرایند، ناموفق و بدون بازپخش خودکار بازیابی می‌شود.

`.env.example` با config مصرف‌شده هماهنگ است. هر سه gate `LAUNCHLANE_ENABLE_MUTATIONS`، `LAUNCHLANE_ENABLE_LIVE_MODEL` و `LAUNCHLANE_ENABLE_LIVE_LIARA` پیش‌فرض false هستند. حتی فعال‌کردن flag mutation، adapter زنده یا approval ایجاد نمی‌کند. رمز پنل Liara توکن PaaS نیست؛ کلید مدل فقط به میزبان ثابت BoxAPI مجاز است. probe واقعی به نشانی HTTPS مجاز همان برنامه در حساب‌ها یا `LAUNCHLANE_PROBE_ORIGINS` نیاز دارد؛ تنظیم مدیر مقدم است، redirect و IP خصوصی رد می‌شوند. تا تطبیق حساب، این gateها خاموش بمانند.

پس از آماده‌شدن اعتبار و تعیین مدل مجاز، smoke کم‌مصرف و صریح زیر حداکثر دو درخواست واقعی به BoxAPI می‌فرستد. این فرمان در checkها اجرا نمی‌شود و gate ذخیره‌شده را تغییر نمی‌دهد:

```text
npm run smoke:model -- --live
```

برای `gpt-6-luna` در مسیر Chat Completions، `MODEL_REASONING_EFFORT=none` برای ابزارخوانی لازم بود؛ بدون آن سرویس 400 داد. مدل‌های دیگر این نصب هنوز تست نشده‌اند. فهرست مدل‌های Chat مجاز در server enforce می‌شود؛ نه endpoint/provider پنهان داریم و نه fallback خودکار.

## محدوده و دسترسی

MVP یک operator و یک scope مجاز دارد. privileged read/write به session، Host/Origin و در درخواست تغییر، CSRF وابسته‌اند؛ loopback جای authentication نیست. SQLite برای یک process است و approval/attempt به حافظه fallback نمی‌کنند. پاسخ گم‌شده یا قطع process، action را uncertain و write متعارض app را مسدود می‌کند.

بسته‌ها در `.data/source-artifacts/` یا زیر `LAUNCHLANE_STATE_DIR` خصوصی نگهداری می‌شوند؛ سقف هر بسته ۲۴ MiB، کل نگهداری ۱۲۸ MiB و ۳۲ فایل است. پاک‌سازی خودکار فعلاً وجود ندارد. حذف بسته متعلق به approval فعال، آن را قابل اجرا نمی‌کند؛ نگهداری/پاک‌سازی فقط پس از تعیین تکلیف اقدام‌ها انجام شود. پیشنهادهای قدیمی v1 خوانده می‌شوند ولی برای deploy به بسته متصل نیستند و باید دوباره ساخته شوند.

تشخیص source محدود و static است؛ پشتیبانی همه frameworkها، upload/deploy واقعی، قیمت/پلن، env secret-reference و اصلاح واقعی هنوز تکمیل نشده‌اند. probe شبکه‌ای و diagnosis runtime قرارداد آزموده دارند اما روی Liara/اختلال واقعی سنجیده نشده‌اند. پشتیبانی چند process، میزبانی عمومی و پایش ۲۴ساعته در محدوده این نسخه نیستند.

قابلیت پیاده‌نشده و بررسی زنده انجام‌نشده در گزارش وضعیت محصول صریح ثبت می‌شوند.
